# Linux Bootstrap

The Linux Bootstrap is distributed as a Dinit service package (dinit.d).
Its service descriptions are generated by the C++ build-host program
dinit-bootstrap-gen; runtime environment inspection is implemented in
the target-side C++ program dinit-bootstrap.

The initial framework provides environment detection, procfs/sysfs setup, and an
`early-prepare.target`. Device, cgroup, sysctl, binfmt, and shutdown services
will be added after their ordering and failure rules have been validated against
Dinit's service semantics and the dinit-rc / dinit-chimera references.

## Environment policy

* Bare metal and virtual machines use the strict host policy: required initialization
  operations must succeed; a failure fails the service and blocks dependent boot targets.
* Containers use a separate policy. An operation explicitly marked container-skippable
  may fail with a diagnostic and be treated as skipped; required operations still fail
  startup. Existing mounts are detected and are not mounted a second time.
* The initial pseudo-filesystem policy treats procfs as required in every environment,
  while sysfs setup may be skipped in a container if the mount cannot be performed.
* A nested PID namespace is sufficient to select container policy even when its runtime
  (Docker/LXC/etc.) cannot be identified. Unknown environments do not receive container
  skip behavior.
* The environment service requires Dinit to be PID 1 in its current PID
  namespace. A non-PID-1 Dinit instance must not run system Bootstrap.
* Linux 4.9 is the minimum compatibility target. Newer kernel interfaces
  are optional and must be detected at runtime.

The runtime detector writes its result to /run/dinit/environment. The state records PID 1 and PID namespace information, container/VM classification, the root filesystem type, procfs/sysfs mount status, the /dev filesystem type, and cgroup v1/v2/hybrid mount presence. Unknown detection results remain explicitly unknown; they are not silently treated as host defaults.
The `bootstrap-environment` service remains supervised after detection. It uses Dinit's
`ready-notification = pipefd:4` mechanism and reports readiness only after the state file has
been written, preventing dependent services from racing environment detection. The generated
`bootstrap-proc` and `bootstrap-sys` scripted services depend on it; `pseudofs` waits for both,
and `early-prepare.target` depends on `pseudofs`.

## Build model

The generator is compiled for and run on the build machine. The runtime
detector is compiled for the target machine. This distinction is required
for cross-compilation (for example, Android and other aarch64 targets).
