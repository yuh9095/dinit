# Linux Bootstrap

The Linux Bootstrap is distributed as a Dinit service package (dinit.d).
Its service descriptions are generated by the C++ build-host program
dinit-bootstrap-gen; runtime environment inspection and system preparation
are implemented by the target-side C++ program dinit-bootstrap.

The current implementation is the first, deliberately narrow part of the
service package: PID 1 launch-contract checking, procfs/sysfs preparation,
environment classification, and the early preparation target. Device
management, cgroups, filesystems, generic Linux services, and shutdown
integration remain subsequent implementation stages; they are not claimed
to be implemented by this initial package.

## Environment policy

* Bare metal and virtual machines use the strict host policy.
* A confirmed container may skip only operations explicitly marked
  container-skippable. Procfs remains mandatory.
* A nested PID namespace alone is not sufficient to select container policy.
  Ptrace state is not treated as evidence of proot or a container.
* Positive virtualization evidence takes precedence over container markers,
  so virtual machines retain the strict host policy.
* Runtime helpers are launched by Dinit as direct children of PID 1 in the
  current PID namespace. The helper checks its parent PID; the helper itself
  is not expected to have PID 1.
* Linux 4.9 is the minimum compatibility target. Newer kernel interfaces
  are optional and must be detected at runtime.

The runtime detector writes its result to /run/dinit/environment. It
records PID namespace information, container/VM classification, the root
filesystem type, procfs/sysfs mount status, the /dev filesystem type, and
cgroup v1/v2/hybrid mount presence. Unknown detection results are not
silently treated as a confirmed container.

## Service ordering

The generated dependency order is:

1. bootstrap-proc ensures procfs is mounted.
2. bootstrap-environment inspects /proc and writes environment state.
3. bootstrap-sys prepares sysfs using the recorded environment policy.
4. pseudofs aggregates the procfs and sysfs services.
5. early-prepare.target depends on pseudofs.

This ordering is intentional: environment detection reads /proc, so it
must not be a prerequisite of procfs setup. The environment process uses
Dinit's ready-notification = pipefd:4 mechanism and reports readiness only
after the state file has been written.

## Build model

The generator is compiled for and run on the build machine. The runtime
helper is compiled for the target machine. This distinction is required for
cross-compilation (for example, Android and other aarch64 targets).
