# Linux Bootstrap

The Linux Bootstrap is distributed as a Dinit service package (dinit.d).
Its service descriptions are generated by the C++ build-host program
dinit-bootstrap-gen; runtime environment inspection is implemented in
the target-side C++ program dinit-bootstrap.

The initial framework deliberately contains only the environment service and
an early-prepare target. Filesystem, device, cgroup, sysctl, binfmt, and
shutdown services will be added after their ordering and skip rules have been
validated against Dinit's service semantics and the dinit-rc / dinit-chimera
references.

## Environment policy

* Bare metal and virtual machines use the same host initialization policy.
* Containers use a container policy and must not repeat host-owned mounts or
  other host setup.
* Unknown environments are handled conservatively.
* The environment service requires Dinit to be PID 1 in its current PID
  namespace. A non-PID-1 Dinit instance must not run system Bootstrap.
* Linux 4.9 is the minimum compatibility target. Newer kernel interfaces
  are optional and must be detected at runtime.

The runtime detector writes its result to /run/dinit/environment. The state records PID 1 and PID namespace information, container/VM classification, the root filesystem type, procfs/sysfs mount status, the /dev filesystem type, and cgroup v1/v2/hybrid mount presence. Unknown detection results remain explicitly unknown; they are not silently treated as host defaults.
The service remains supervised after detection so that Dinit can treat the
environment service as active until the rest of the boot sequence is stopped.

## Build model

The generator is compiled for and run on the build machine. The runtime
detector is compiled for the target machine. This distinction is required
for cross-compilation (for example, Android and other aarch64 targets).
